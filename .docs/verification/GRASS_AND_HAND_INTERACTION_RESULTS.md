# Grass and hand interactions — 2026-09-08

The user requested familiar Minecraft-style grass behaviour, a better fist-breaking animation, visible held items and simpler targeting. This revision implements those behaviours with Rivet Reach's own code, rig and textures. [Minecraft's official grass overview](https://www.minecraft.net/en-us/article/block-week-grass) describes the reference behaviour; no third-party models, textures, animations or source code were imported.

## Delivered behaviour

- Grass mined with fists produces one dirt item; dirt and stone retain their existing drops and mining durations. Placement and pickup still conserve the selected quantities.
- Nearby grass receives random 20 Hz ticks. It spreads to exposed adjacent dirt, including small slope steps, and decays under cover. A roof above the column blocks growth; removing it restores sky exposure. Changes use session edit records and persist through chunk unload/reload and origin shifts. Pausing freezes ticks; distant/unloaded terrain receives no catch-up. [The simulation contract](../SIMULATION.md#13-grass-random-ticks--first-step-feedback) owns sampling, bounds and light limitations.
- First person shows the right hand. Blender-authored `Mine` and `FP_Mine` clips now use a 0.3-second lifting, inward/downward sweep and recovery. Held mining repeats it; release finishes the active gesture before settling. Successful placement triggers a single gesture. Full-body mining retains its upper-body mask over locomotion.
- The selected grass, dirt or stone block rests on a flat upward-facing palm through `BlockSocket`, follows the animation and hotbar, and disappears when the stack is empty or menus are open. Appearance changes reattach it to the rebuilt rig. F5 inspection attaches it to the full-body hand. The view compensates for FBX bone units and first-person FOV; it owns no inventory quantities.
- One thin, dark outline surrounds the aimed block, with consistent screen-space width and terrain occlusion. The previous coloured destination box is removed. Placement still uses the aimed face and validates residency, occupancy, player/pile overlap and quantity, reporting rejected attempts.

The subsequent grip feedback adds dedicated open-palm block, closed one-hand handle and closed two-hand handle poses. Forearm roll carries pronation; neutral fists and tool grips align the wrist with the forearm. The block is 14 cm wide and its bottom sits against the palm, with straight fingers beneath it. Tool fingers curl around a 36 mm shaft and the opposing thumb closes the grip. Item and hand move together, including walking bob, camera sway, placement and mining. Grip changes blend with a 25 ms half-life; objects appear after the grip reaches 98.5% (about 152 ms), keeping transitional fingers from visibly passing through a prop.

The original Blender sword and pickaxe are **cosmetic grip review assets**, accessible in **Rivet Reach → Review hand grips** during an expedition. They do not add weapon/tool inventory, recipes, damage or mining bonuses. The two-hand pose enables the support arm on the existing skeleton. Closing the panel restores inventory-driven presentation.

## Source and reproduction

`Tools/create_player_assets.py` owns the poses. `Tools/revise_player_interactions.py` rebakes the current animation library into existing male/female `.blend` and FBX files, preserving topology, material slots and skin atlases. `Tools/render_player_hands.py` renders five source poses using the same right-arm visibility selection. `Tools/create_grip_review_assets.py` creates the original cosmetic props; `Tools/render_grip_review.py` renders the skinned grip contacts and `Tools/check_grip_contacts.py` measures palm/shaft clearance and wrist angles. `Tools/check_player_assets.py` checks normalized weights, relative texture references, deformation bounds, crouch headroom and loop continuity. Existing source counts remain 31,734/32,126 full-body triangles, 40 deforming bones, two non-deforming attachment sockets, one material and 28 clips.

The visible first-person arm is **5,248 triangles**, down from the previous 10,496-triangle pair. Together with the retained 8,544-triangle torso/legs this is **13,792 visible character triangles**, plus **12** for a selected block. The full selected mesh still supplies the separate shadow view; earlier shadow-cost limitations remain in the [body/scene report](BODY_AND_SCENE_POLISH_RESULTS.md#rendering-cost-and-remaining-review). The two-hand preview renders both arms (10,496 triangles); the original sword/pickaxe add 3,366/2,876 triangles respectively. Those preview costs are separate from ordinary block selection. The item uses one small cached cube mesh per encountered terrain type and the existing terrain texture array. The target outline uses 24 small triangles. Counts exclude repeated rendering passes and do not establish a frame-rate guarantee.

Build with `Tools/Build-Windows.ps1`; run `Tools/Verify-POC.ps1` for the full terrain/inventory/interaction regression and `Tools/Verify-Player.ps1` for the imported pose and animation suite. A short iteration uses `-rr-verify -rr-interaction-review -rr-output <directory>`; its report explicitly identifies that smaller workload. Grass growth fixtures advance the real random-tick scheduler faster than wall time, and are created only in explicit verification mode. They are not generated world structures. The Editor menu **Rivet Reach → Verify Editor Play startup** separately checks two normal Play/Stop cycles.

## Review limits

Grass currently uses **direct sky exposure**, rather than Minecraft's complete indirect/block-light propagation. The existing palette is opaque, with fixed daylight and no torch/light-source gameplay. Full voxel lighting, transparent materials and day/night effects remain later work. Random growth is intentionally gradual and has no guaranteed per-block deadline.

The new motion is an original rigged interpretation of the requested interaction style; it is not a frame-for-frame animation port. First-person hands and props share a compressed near depth interval, keeping proper finger/handle and palm/block occlusion while staying in front of nearby terrain. F5 uses ordinary depth. Neither this display nor the full character preview changes collision or interaction reach. Source texture/likeness and wider gameplay acceptance remain under user review. World progress is still session-only.
